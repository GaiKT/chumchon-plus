# Design System: ชุมชนพลัส (MASTER)

เอกสารหลักของหน้าตาและการใช้งานทั้งระบบ ถ้าหน้าไหนต้องต่างจากนี้ ให้เขียนไว้ใน `design-system/pages/<ชื่อหน้า>.md` และไฟล์นั้นมีผลเหนือไฟล์นี้

> สถานะ: **ใช้งานจริง** เลือกแนวทาง **C (contrast สูง)** แล้ว token ทั้งหมดอยู่ใน `src/app/globals.css`

---

## 1. ผู้ใช้และสภาพการใช้งาน

| ปัจจัย | สภาพจริง | ผลต่อการออกแบบ |
|---|---|---|
| ผู้ใช้ | ผู้ใหญ่บ้านและผู้ช่วย อายุ 40-70 ปี บางคนสายตายาว | ตัวอักษรใหญ่ contrast สูง ปุ่มใหญ่ คำอธิบายเป็นข้อความ ไม่พึ่ง icon อย่างเดียว |
| อุปกรณ์ | Android ราคาประหยัด จอ 360-412px | ออกแบบที่ 360px ก่อน ไม่ใช้ effect หนัก |
| สถานที่ | กลางแจ้ง แดดจ้า ศาลาหมู่บ้าน | contrast เกินขั้นต่ำ ไม่ใช้สีอ่อนบอกสถานะ ใช้เส้นกรอบชัดแทนเงา |
| เครือข่าย | 3G/4G ไม่เสถียร | ไม่มีรูปภาพประกอบ ฟอนต์เดียว ไม่มี animation หนัก |
| งาน | ค้นหา → ดู → คัดลอก/โทร ใช้ครั้งละไม่ถึง 1 นาที | หน้าแรกคือช่องค้นหา ทุกอย่างอยู่ใกล้นิ้ว ไม่ต้องเลื่อนหา |
| บริบท | ข้อมูลราชการและข้อมูลส่วนบุคคล | ดูน่าเชื่อถือ เรียบร้อย ไม่เล่นสนุก ภาษาไทยทางการ |

**หลักการ 4 ข้อ** (ใช้ตัดสินเมื่อขัดกัน เรียงตามลำดับความสำคัญ)
1. **อ่านออกกลางแดด** ชนะความสวย
2. **กดถูกครั้งแรก** ชนะความกะทัดรัด
3. **ชัดเจน** ชนะความสั้น (ปุ่มมีข้อความเสมอ)
4. **เร็วบน 3G** ชนะลูกเล่น

## 2. รูปแบบ (Style)

- **Flat + เส้นกรอบดำชัด** ไม่ใช้ glassmorphism, gradient, เงา หรือ blur
- แยกชั้นด้วย **เส้นกรอบ + พื้นหลัง** แทนเงา (เงาหายเมื่ออยู่กลางแดด)
- Theme สว่างอย่างเดียว (ตัดสินใจไว้แล้ว ไม่ทำ dark mode)
- Icon: **Lucide** (`lucide-react` bundle ไปกับแอป ไม่ใช้ CDN) stroke 2.5 ขนาด 24px **ทุก icon ต้องมีข้อความกำกับ** และใส่ `aria-hidden` ห้ามใช้ emoji แทน icon

## 3. สี

ทุกค่าใช้เป็น **semantic token** ใน `globals.css` (`@theme`) สีและขนาดตัวอักษรเริ่มต้นของ Tailwind **ถูกลบทิ้งแล้ว** (`--color-*: initial`, `--text-*: initial`) ถ้าใส่ `gray-500` หรือ `text-sm` จะไม่มีผลเลย

### 3.1 Token สี

| Token (Tailwind) | ค่า | ใช้กับ | Contrast |
|---|---|---|---|
| `background` | `#FFFFFF` | พื้นหลังหน้า การ์ด ช่องกรอก | – |
| `foreground` | `#000000` | ข้อความทุกระดับ กรอบช่องกรอก กรอบการ์ด กรอบปุ่มรอง | 21 : 1 |
| `white` | `#FFFFFF` | ข้อความบนแถบบนและปุ่มหลัก | – |
| `primary` | `#172554` กรมท่าเข้ม | แถบบน ปุ่มหลัก ปุ่มโทร | ขาวบนพื้นนี้ 14.7 : 1 |
| `primary-pressed` | `#000000` | ปุ่มหลักตอนกด | – |
| `highlight` | `#FEF08A` เหลือง | การ์ดคนที่เลือก ป้าย "บ้านว่าง" กล่องเตือน รายการเมนูที่ชี้อยู่ อุปกรณ์นี้ | ดำบนพื้นนี้ 19 : 1 |
| `focus` | `#FACC15` | วง focus (ดูหัวข้อ 6) | – |
| `muted` | `#E5E7EB` | การ์ดอดีตสมาชิก ปุ่มรองตอนกด | ดำบนพื้นนี้ 16 : 1 |

**ไม่มีข้อความสีเทา** ข้อความรองใช้ `foreground` เหมือนกันแต่ตัวบางกว่าหรือเล็กกว่า (`text-caption`) แทนการทำให้จาง

### 3.2 แนวทางที่ไม่ได้เลือก (เก็บไว้อ้างอิง)

ขั้นที่ 2 ทำ mock 3 แนวทาง: (A) ทางการ น้ำเงิน `#1D4ED8` (B) อบอุ่น เขียว `#166534` กับพื้นครีม และ (C) contrast สูง ผู้ใช้เลือก C เพราะอ่านกลางแดดได้ดีที่สุด ซึ่งตรงกับหลักการข้อ 1

### 3.3 สีความหมาย (ต้องมีข้อความหรือ icon กำกับเสมอ)

| Token | ค่า | Contrast | ใช้กับ |
|---|---|---|---|
| `danger` | `#B91C1C` | 6.5 : 1 บนขาว | กรอบช่องที่ผิด ปุ่มยืนยันลบ |
| `danger-strong` | `#991B1B` | 8.3 : 1 บนขาว | ข้อความ error ปุ่ม "ลบข้อมูล..." "ออกจากระบบ" ในเมนู |
| `danger-surface` | `#FEE2E2` | `danger-strong` บนพื้นนี้ 6.8 : 1 | กล่องยืนยันการลบ ป้าย "ปิดการใช้งานแล้ว" |

คำเตือนและสถานะอื่นไม่มีสีของตัวเอง ใช้ `highlight` + กรอบดำ + icon (กล่องเตือน, "บ้านว่าง") หรือป้ายกรอบดำ ("ย้ายออก", "เสียชีวิต") toast "คัดลอกเรียบร้อยแล้ว" เป็นพื้นดำตัวอักษรขาวพร้อม icon ✓

**ห้าม** ใช้ความจางลง (opacity) เพื่อบอกว่าคนย้ายออกหรือเสียชีวิต เพราะกลางแดดจะอ่านไม่ออก ให้ใช้ป้ายข้อความ + การ์ดเส้นประพื้น `muted`

## 4. ตัวอักษร

- ฟอนต์เดียว: **Noto Sans Thai** (self-host ผ่าน `next/font`) ใช้ weight 400 (เนื้อความ), 600 (เน้นเล็กน้อย), 700 (หัวข้อ ชื่อคน label ปุ่ม)
- ขนาดฐาน `html { font-size: 125% }` = **20px** และยังตามการตั้งค่าขนาดตัวอักษรของเบราว์เซอร์
- ภาษาไทยมีสระบน-ล่างและวรรณยุกต์ **line-height ต้องไม่ต่ำกว่า 1.6** สำหรับเนื้อความ และ 1.35 สำหรับหัวข้อ
- ตัวเลข (บ้านเลขที่ เบอร์โทร) ใช้ `tabular-nums`
- **ขั้นต่ำ 18px** (`text-caption`) theme ไม่มีขนาดเล็กกว่านี้

| Token | ขนาด | ใช้กับ |
|---|---|---|
| `text-caption` | 18px | hint, เวลาใช้งานล่าสุด, "(จำเป็น)" |
| `text-body` | 20px | เนื้อความ ค่าในช่องกรอก ข้อความบนปุ่ม |
| `text-title` | 24px | ชื่อคนบนการ์ด หัวข้อ section ข้อความในช่องค้นหา |
| `text-heading` | 28px | หัวข้อหน้า เช่น "บ้านเลขที่ 12" |

## 5. ระยะห่างและขนาด

- `--spacing: 4px` ระบบ 4px ไม่ขึ้นกับขนาดตัวอักษร (`p-4` = 16px) ใช้ 4, 8, 12, 16, 24, 32
- ขอบหน้าจอซ้าย-ขวา **16px** ความกว้างเนื้อหาสูงสุด 576px (`max-w-xl`) จอใหญ่จะอยู่กลางจอ
- ระยะในการ์ด 16px ระหว่างการ์ด 12px ระหว่าง section 24px
- **พื้นที่กด:** ช่องกรอกและปุ่มทั่วไป 56px (`min-h-14`) ปุ่มบันทึก/เข้าสู่ระบบ 60px ปุ่มในการ์ด 52px ไม่มีอะไรต่ำกว่า **48px** (`e2e/pwa.spec.ts` ตรวจทุกปุ่ม ลิงก์ และช่องกรอก) ระยะระหว่างพื้นที่กด ≥ 8px
- มุมโค้ง 8px (`rounded-md`) ทุกอย่าง ป้ายใช้ 4px (`rounded-sm`)
- กรอบ: ช่องกรอก การ์ด ปุ่มรอง **2px ดำ** การ์ดคนที่เลือกและกล่องเตือน 3px ช่องที่ผิด 3px สีแดง

## 6. Component และสถานะ

ทุก component มีครบ 5 สถานะ: ปกติ / กดอยู่ / focus / ปิดใช้งาน / กำลังทำงาน **ห้ามให้ขนาดเปลี่ยนเมื่อเปลี่ยนสถานะ** (layout ห้ามขยับ)

| Component | กติกา |
|---|---|
| **ปุ่มหลัก** | 1 หน้ามีได้ **ปุ่มเดียว** เช่น "บันทึกข้อมูล" พื้น `primary` ตัวอักษรขาว กดอยู่ = `primary-pressed` กำลังทำงาน = "กำลังบันทึกข้อมูล..." และกดซ้ำไม่ได้ **ข้อยกเว้น:** ปุ่มโทรในการ์ดสมาชิกใช้สี `primary` ได้ทุกการ์ด เพราะเป็นงานหลักของหน้านั้น |
| **ปุ่มรอง** | กรอบดำ 2px พื้นขาว เช่น "ยกเลิก" "คัดลอก" "แก้ไข" |
| **ปุ่มโทร** | icon โทรศัพท์ + เบอร์ (คำว่า "โทร" อยู่ใน `sr-only`) เพื่อให้วางคู่กับปุ่ม "คัดลอก" ได้ในจอ 360px |
| **ปุ่มอันตราย** | ข้อความ `danger-strong` ขีดเส้นใต้ แยกไว้ท้ายหน้าใต้เส้นคั่น ห่างจากปุ่มบันทึกข้อมูล ≥ 32px ต้องยืนยัน 2 ชั้น (เปิดกล่อง แล้วพิมพ์ชื่อ) |
| **ลิงก์** | มีขีดเส้นใต้เสมอ พื้นที่กดสูง ≥ 48px ลิงก์ที่เป็นการกระทำ (เพิ่ม แก้ไข) ใช้หน้าตาปุ่มรอง |
| **Focus** | วง 2 สี: เหลือง `focus` 4px + ดำด้านนอก 2px (`:focus-visible` ใน `globals.css`) เห็นได้ทั้งบนแถบบนสีเข้มและบนพื้นขาว |
| **ช่องกรอก** | label ตัวหนาอยู่บนช่องเสมอ (ห้ามใช้ placeholder แทน label) ช่องที่จำเป็นมี "(จำเป็น)" ต่อท้าย label hint อยู่ใต้ช่อง error อยู่ใต้ช่องพร้อม icon + ข้อความที่บอกทั้งสาเหตุและวิธีแก้ กรอบสีแดง 3px เมื่อผิด select ใช้ของเบราว์เซอร์พร้อมลูกศร Lucide |
| **ช่องที่มีค่าให้เลือก** | ถ้าค่าส่วนใหญ่ซ้ำกัน ให้ใช้ `ChoiceField`: select ของค่าที่ใช้บ่อย + "อื่นๆ (พิมพ์เอง)" ที่เปิดช่องพิมพ์ เช่น คำนำหน้า ความสัมพันธ์กับหัวหน้าครัวเรือน คุ้ม/ซอย (จากคุ้มที่มีในหมู่บ้าน) |
| **วันที่** | `BirthDateField`: select 3 ช่อง วัน / เดือน (ชื่อเดือนไทย) / ปี พ.ศ. ไม่ใช้ปฏิทินแบบ popup เพราะวันเกิดต้องย้อนหลายสิบปี และ select บนมือถือเป็นวงล้อใหญ่ วันที่ไม่มีจริงเลือกไม่ได้ มีปุ่ม "ไม่ทราบวันเกิด" |
| **ฟอร์มที่บันทึกไม่ผ่าน** | กล่องสรุป "บันทึกไม่สำเร็จ กรุณาแก้ไข N ช่องที่มีเครื่องหมาย" ด้านบน (`FormErrorSummary`) และ focus ย้ายไปช่องแรกที่ผิด (`ActionForm` prop `result`) |
| **ช่องค้นหา** | สูง 60px ตัวอักษร 24px icon แว่นขยายด้านซ้าย ปุ่มล้าง (×) ด้านขวา ช่องค้นหาและ checkbox ติดด้านบนจอ (sticky) เมื่อเลื่อนดูผล "กำลังค้นหา..." อยู่บรรทัดเดียวกับ checkbox |
| **การ์ดผลค้นหา** | ทั้งการ์ดกดได้ มีลูกศร › ด้านขวา กดอยู่ = พื้น `muted` อดีตสมาชิกใช้กรอบเส้นประ + ป้ายสถานะ |
| **การ์ดสมาชิก** | คนที่เลือกมาใช้กรอบดำ 3px + พื้น `highlight` ป้าย "หัวหน้าครัวเรือน" พื้นดำตัวอักษรขาว อดีตสมาชิกใช้การ์ดเส้นประพื้น `muted` + ป้ายสถานะ |
| **ป้ายสถานะ** | ข้อความเสมอ เช่น "ย้ายออก" ไม่ใช้จุดสีอย่างเดียว |
| **Toast** | ด้านล่างจอ ห่างขอบล่าง 24px + safe area หายใน 3 วินาที ใช้ `role="status"` และมี icon ✓ |
| **กล่องเตือน** | `Alert variant="warning"` พื้น `highlight` กรอบดำ 3px + icon สามเหลี่ยม เช่น ต้องเลือกหัวหน้าคนใหม่ / `variant="error"` กรอบแดง 3px |
| **Empty state** | ข้อความบอกว่าเกิดอะไร + สิ่งที่ทำต่อได้ เช่น "ไม่พบลูกบ้านที่ตรงกับคำค้น" + "ลองพิมพ์ชื่อเล่น หรือบ้านเลขที่แทน" |

**Component แบบ shadcn/ui** อยู่ใน `src/components/ui/` เขียนเองตามรูปแบบ shadcn (`cva` + `cn`) ไม่ได้ใช้ CLI เพราะ CLI จะเขียนทับ token และใส่ dark mode
- `Button` / `buttonVariants` (primary, secondary, danger, link, onPrimary × default, large, small) ใช้กับ `<Link>` ได้ด้วย
- `Badge` (strong, outline, highlight, danger), `Alert` (error, warning)
- `DropdownMenu` จาก `radix-ui` สำหรับเมนูบัญชี ใช้ `modal={false}` เพราะแบบ modal ซ่อนส่วนอื่นด้วย `aria-hidden` ทั้งที่ยังกดได้ (axe แจ้ง)
- ช่องกรอก select และ checkbox ใช้ element ของเบราว์เซอร์ ไม่ใช้ Sonner (toast เดิมเบากว่า)
- `cn` ใน `src/lib/utils.ts` สอน tailwind-merge ให้รู้จัก `text-caption/body/title/heading` แล้ว

**ข้อห้ามเชิงเทคนิค:** ทุกฟอร์มที่มี select ต้องใช้ `ActionForm` ห้ามเปลี่ยนกลับเป็น `<form action>` เพราะการ reset อัตโนมัติของ React ทำให้บันทึกค่าผิด (bug ที่เจอใน #10)

## 7. โครงหน้าและการนำทาง

- ไม่มี bottom navigation (หน้าหลักมีหน้าเดียวคือค้นหา)
- **แถบบนสุด (app bar) ทุกหน้า** (`PageShell` ใน `src/app/app-bar.tsx`): ซ้าย = ปุ่ม "หน้าแรก" (กดครั้งเดียวกลับหน้าค้นหา) หรือชื่อแอปในหน้าแรก ขวา = เมนู (ชื่อผู้ใช้, ความเปลี่ยนแปลงรายเดือน, อุปกรณ์ที่เข้าสู่ระบบ, รายการที่ถูกลบ, ออกจากระบบ) ปุ่ม "‹ ย้อนกลับ" อยู่บนสุดของเนื้อหาหน้า (หน้าครัวเรือนใช้ "กลับไปหน้าค้นหา")
- หลังบันทึกหรือลบสำเร็จ ใช้ `showAfterChange()` ซึ่งแทนที่หน้าฟอร์มในประวัติ (กดย้อนกลับแล้วไม่กลับไปที่ฟอร์ม) และล้างหน้าที่ cache ไว้ ฟอร์มแก้ไขใส่ `key` จากข้อมูลที่โหลด เพราะ Next เก็บหน้าที่เคยเปิดไว้ ถ้าไม่ใส่จะแสดงค่าเก่า
- "ออกจากระบบ" อยู่ในเมนู แยกจากปุ่มใช้งานทั่วไป
- หน้าแรก: ช่องค้นหา (sticky) → "กรองตามอายุ" 3 ปุ่ม → "ตัวกรองเพิ่มเติม" (ปิดไว้) → "พบ N คน" + เงื่อนไขที่ใช้ → ผลลัพธ์ → "+ เพิ่มบ้าน" ไว้ล่างสุด (ใช้ไม่บ่อย) การค้นหาและการดูรายชื่อตามเงื่อนไขอยู่หน้าเดียวกัน ไม่แยกหน้า
- หน้าครัวเรือน: หัวข้อบ้านเลขที่ → สมาชิก → อดีตสมาชิก → การจัดการ (เพิ่มสมาชิก, แก้ไขข้อมูลบ้าน) ไว้ล่างสุด
- กดย้อนกลับแล้วต้องกลับไปที่เดิมพร้อมคำค้น

---

## 8. การเคลื่อนไหว

- ใช้แค่การเปลี่ยนสี 150ms (ตอนกด)
- ปิดทั้งหมดเมื่อผู้ใช้ตั้งค่า `prefers-reduced-motion`
- ไม่มี skeleton หรือ shimmer ใช้ข้อความ "กำลังโหลด..." หรือ "กำลังค้นหา..." ซึ่งชัดกว่าสำหรับผู้ใช้กลุ่มนี้

## 9. ข้อความ (ภาษาไทย)

- ภาษาไทยทางการแต่สั้น ตรวจด้วย skill `ebm-thai` ก่อนส่งงาน
- ปุ่มขึ้นต้นด้วยคำกริยา: "บันทึกข้อมูล" "คัดลอก" "เพิ่มสมาชิก" "ออกจากระบบ"
- คำที่ใช้ตาม glossary ของ `ebm-thai`: "ย้อนกลับ" (ไม่ใช่ "กลับ"), "บันทึกข้อมูล", "ยืนยันการลบข้อมูล", "โปรดเลือก", placeholder ขึ้นต้นด้วย "กรอก", toggle ใช้ "เปิดใช้งาน" / "ปิดการใช้งาน", ข้อความสำเร็จลงท้ายด้วย "เรียบร้อยแล้ว", ไม่ใช้ "คุณ" หรือ "ฉัน"
- **ข้อยกเว้นจาก glossary:** ใช้ "แตะ" แทน "คลิก" เพราะเป็นแอปบนจอสัมผัส และ error จากการกรอกฟอร์มผิดไม่ต้องขึ้นต้นด้วย "เกิดข้อผิดพลาด" (ใช้เฉพาะเมื่อระบบขัดข้อง เช่น คัดลอกไม่สำเร็จ)
- ข้อความ error = สาเหตุ + วิธีแก้ เช่น "วันเกิดไม่ถูกต้อง ใช้รูปแบบ วว/ดด/ปปปป เช่น 15/03/2515"
- ใช้ปี พ.ศ. ทุกที่ที่แสดงวันที่
- ชื่อเล่นแสดงเป็น "ชื่อเล่น แดง" ไม่ใช้วงเล็บหรือเครื่องหมายคำพูด

## 10. สิ่งที่ห้ามทำ

- ห้ามใช้ข้อความสีเทา (theme ไม่มีให้ใช้แล้ว)
- ห้ามบอกสถานะด้วยสีหรือความจางอย่างเดียว
- ห้ามมีปุ่มที่มีแต่ icon ไม่มีข้อความ (ยกเว้นปุ่มล้างในช่องค้นหาที่มี `aria-label`)
- ห้ามใช้ placeholder แทน label
- ห้ามใช้รูปภาพประกอบ หรือ font/CDN จากภายนอก (ขัดกับ CSP และช้าบน 3G)
- ห้ามใช้ hover เป็นทางเดียวที่จะเห็นข้อมูล
- ห้ามปิดการซูมหน้าจอ
